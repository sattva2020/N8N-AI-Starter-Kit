# Руководство для AI-агентов по работе с проектом N8N AI Starter Kit

## 1. Обзор архитектуры

Этот проект использует Docker Compose для оркестрации множества сервисов, создавая комплексную self-hosted AI-платформу.

- **Ядро системы**: `n8n` (`docker-compose.yml`) является центральным компонентом для автоматизации рабочих процессов.
- **AI/LLM**: `Ollama` (`compose/ollama-compose.yml`) используется для локального запуска языковых моделей.
- **Векторное хранилище**: `Qdrant` (`docker-compose.yml`) служит для хранения эмбеддингов и реализации RAG.
- **Базы данных**: `PostgreSQL` (основная БД для n8n) и `Neo4j` (для графа знаний через `Graphiti`).
- **Маршрутизация**: `Traefik` (`docker-compose.yml`) выступает в роли обратного прокси, управляя доступом ко всем веб-интерфейсам.
- **Конфигурация**: Вся конфигурация управляется через файл `.env`, который генерируется из `template.env` с помощью скрипта `scripts/setup.sh`.

## 2. Ключевые рабочие процессы

### Запуск и установка

- **Основной скрипт запуска**: `start.sh`. Это "умный" скрипт, который автоматически определяет оптимальный профиль (`cpu`, `gpu-nvidia`, `developer`), проверяет конфигурацию и запускает систему. **Всегда используйте его для запуска.**
- **Первоначальная настройка**: `scripts/setup.sh`. Этот скрипт используется для интерактивной настройки или быстрой установки на основе `template.env`. Он генерирует `.env` файл с необходимыми секретами.
- **Диагностика**: `scripts/diagnose.sh`. Используйте этот скрипт для проверки состояния системы, портов и конфигурации.

**Пример запуска:**
```bash
# Запустит систему с автоопределением профиля
./start.sh

# Явный запуск с профилем cpu
./start.sh cpu
```

### Управление workflow

- **Автоматический импорт**: Сервис `services/n8n-importer` отвечает за автоматический импорт рабочих процессов (workflows) в `n8n` при старте системы.
- **Структура Workflows**: Рабочие процессы организованы в директории `n8n/workflows/` по категориям (`production/`, `testing/`, `examples/`).

## 3. Соглашения и паттерны проекта

- **Структура проекта**: Проект придерживается строгих правил организации файлов, описанных в `ai-instructions/PROJECT_STRUCTURE_GUIDELINES.md`. **Критически важно поддерживать чистоту в корневой директории.**
- **Конфигурация через `.env`**: Никогда не вносите секреты напрямую в `docker-compose.yml`. Всегда используйте переменные из `.env`.
- **Модульность Compose**: Дополнительные сервисы вынесены в отдельные файлы в директории `compose/` и подключаются через профили в основном `docker-compose.yml`.
- **Скрипты**: Все вспомогательные скрипты должны находиться в директории `scripts/` и быть разделены по назначению (например, `deployment`, `maintenance`, `utils`).

## 4. Интеграции и взаимодействие компонентов

- **n8n <> Ollama**: `n8n` обращается к `Ollama` по внутреннему сетевому имени `ollama:11434` для выполнения задач, связанных с LLM.
- **n8n <> Qdrant**: `n8n` использует `Qdrant` для поиска по векторам. Адрес: `qdrant:6333`.
- **Traefik и домены**: `Traefik` автоматически обнаруживает сервисы через лейблы в `docker-compose.yml` и настраивает для них доступы по доменам, указанным в `.env` (например, `N8N_DOMAIN=n8n.your-domain.com`).
- **Постоянные данные**: Данные сервисов (PostgreSQL, n8n, и т.д.) хранятся в Docker-томах (volumes), определенных в `docker-compose.yml`.

## 5. Приоритеты для AI-агента

1.  **Изучи `start.sh` и `scripts/setup.sh`**: Это ключевые скрипты для понимания жизненного цикла проекта.
2.  **Соблюдай структуру**: Перед созданием или изменением файлов сверься с `ai-instructions/PROJECT_STRUCTURE_GUIDELINES.md`.
3.  **Работай через `.env`**: При добавлении новых сервисов или изменении конфигурации, сначала обнови `template.env`, а затем `.env`.
4.  **Используй профили**: При добавлении новых сервисов интегрируй их через систему профилей в `docker-compose.yml`.

## 7. Полная очистка Docker

Для полного сброса окружения Docker, включая удаление всех контейнеров, сетей и неиспользуемых образов, используется специальный скрипт.

**ВНИМАНИЕ**: Это разрушительная операция, которая удалит все запущенные контейнеры.

**Порядок действий:**
1.  Подключитесь к серверу по SSH.
2.  Перейдите в директорию проекта: `cd /opt/N8N-AI-Starter-Kit`
3.  Запустите скрипт очистки: `./scripts/utils/clean-docker.sh`

**Команда для выполнения из локального терминала:**
```bash
echo y | plink.exe -i "C:\Users\Admin\Documents\ssh_private.ppk" root@37.53.91.144 "cd /opt/N8N-AI-Starter-Kit && ./scripts/utils/clean-docker.sh"
```

После выполнения этого скрипта система будет полностью очищена, и вы можете заново запустить все сервисы с помощью `docker compose up -d`.
