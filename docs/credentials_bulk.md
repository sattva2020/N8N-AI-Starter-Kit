# Массовое создание credentials (CSV / JSON)

Этот документ описывает, как массово создавать credentials в n8n с помощью скрипта
`scripts/create_n8n_credential.sh` через параметр `--bulk-file`.

Коротко:
- Скрипт принимает JSON-массив объектов или CSV-файл с заголовком.
- Каждая запись должна содержать минимум поля `name` и `type` и поле `data` —
  либо JSON-объект, либо строку, которую n8n ожидает в поле `data` конкретного
  типа credentials.
- Для каждой записи можно переопределить `token` (админ-токен n8n) и `n8n_url`.

Формат записей
- Поля (рекомендуемые):
  - name — строка, имя credential в n8n
  - type — тип credential (например, `qdrant`, `http`, `s3` и т.п.)
  - data — JSON-объект или строка; если передаётся CSV, это может быть JSON-строка
  - token — (опционально) admin token для этой записи; если не указан — используется
    токен из CLI/`--env-file`
  - n8n_url — (опционально) базовый URL n8n (например `http://n8n:5678`); если не указан —
    используется значение из `--env-file` или параметров скрипта

Пример JSON (массив):

[
  {
    "name": "qdrant-prod",
    "type": "qdrant",
    "data": {"url": "http://qdrant:6333", "apiKey": "MY_QDRANT_KEY"}
  },
  {
    "name": "ollama",
    "type": "http",
    "data": {"baseUrl": "http://ollama:11434"}
  }
]

Пример CSV (заголовок и строки). Обратите внимание: поле `data` содержит JSON-строку,
поэтому при создании CSV экранируйте кавычки и запятые.

name,type,data,token,n8n_url
qdrant-prod,qdrant,"{\"url\":\"http://qdrant:6333\",\"apiKey\":\"secret\"}",,
ollama,http,"{\"baseUrl\":\"http://ollama:11434\"}",,

Примеры использования

1) Используя `--env-file` (скрипт подгружает defaults из `.env`):

```bash
./scripts/create_n8n_credential.sh --env-file .env --bulk-file data/credentials-bulk.json
```

2) Явно передать токен и файл:

```bash
./scripts/create_n8n_credential.sh --token "MY_ADMIN_TOKEN" --bulk-file data/credentials.csv
См. также: раздел "Как получить admin token (PASTE_ADMIN_TOKEN_HERE)" в `docs/credentials.md` для инструкции по созданию и безопасному хранению токена.
```

Поведение и возвратные коды
- Скрипт парсит файл и для каждой записи выполняет POST в `/rest/credentials`.
- Для каждой записи выводится статус OK / FAIL и тело ответа (если JSON).
- При ошибке парсинга входного файла скрипт завершится с ненулевым кодом.

Рекомендации и предостережения
- Тестируйте сначала небольшим файлом (2-3 записи).
- Поле `data` должно соответствовать структуре, ожидаемой n8n для указанного `type`.
- Если нужно массово создать credentials для Qdrant и вы храните QDRANT_URL/QDRANT_API_KEY
  в `.env`, можно использовать `--env-file .env` и в CSV/JSON опустить `data` — однако в
  таком случае убедитесь, что скрипт/формат поддерживает автозаполнение (см. реализацию).
- Скрипт не делает транзакционного отката: отдельные записи могут быть созданы, даже если
  другие — нет.

Проблемы и отладка
- Если видите HTTP 401/403 — проверьте `--token` или значение в `.env`.
- Для отладки запустите скрипт для одной записи в ручном режиме и проверьте формат `data`.

Где находится скрипт
- `scripts/create_n8n_credential.sh` — смотрите README/скрипты для подробностей и
образцов payload'ов для популярных credential типов (qdrant, http, oauth и т.д.).

Если нужно — могу добавить опцию `--dry-run` (не посылать запросы, только валидировать
и показывать payload), или реализацию батчирования/параллелизации для больших CSV.
